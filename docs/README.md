# Як підтримувати порядок

1. У корені залишаємо лише головну сторінку, README і службові файли.
2. Новий інструмент: `tools/коротка-назва/index.html`.
3. Матеріали заходу: `materials/рік/рррр-мм-дд-коротка-назва/`. Якщо дата ще невідома: `materials/рік/коротка-назва/`.
4. У папці заходу: `README.md` з описом та авторством, `scenario.docx` або `scenario.pdf`, `presentation.pptx`, за потреби папки `images/` і `handouts/`.
5. Назви папок і файлів — латиницею, малими літерами, слова через дефіс. Назви на сторінках — українською.
6. Не створюємо копій «фінал», «фінал2», «новий26». Оновлюємо той самий файл; історію змін зберігає GitHub.
7. Великі відео краще розміщувати на відповідному сервісі та додавати посилання в опис заходу.
8. Посилання між сторінками — відносні: без початкового `/`, щоб вони працювали й у папці репозиторію на GitHub Pages.
9. Перед публікацією перевіряємо авторство, дозволи на матеріали та персональні дані.
10. Новий матеріал додаємо також на відповідну сторінку сайту: саме завантаження файла не створює для відвідувачів посилання на нього.

Спільні ресурси сайту — в `assets/`. Фотографії конкретного заходу — у його папці. Самостійний помічник зберігаємо в одному HTML із вбудованими стилями та скриптами, щоб він залишався автономним.
